# 포트폴리오 콕핏

## 트리거
`포트폴리오 봐줘` · `콕핏` · `집중도` · `환노출` · `내 포트 진단`

## 1. 파이프라인 실행

```bash
python3 -m src.pipelines.cockpit
```

산출물 2개: `reports/cockpit/<날짜>-cockpit.md` · `dashboard/index.html`

입력은 `portfolio/holdings.yaml` 이다. **사람이 수동 갱신한다** — 계좌 연동이 없다.
파일이 없거나 비었으면 편집기를 안내한다:

```bash
python3 -m src.pipelines.editor      # http://127.0.0.1:8765
```

## 2. 신선도를 먼저 본다

리포트 상단의 `보유 현황 갱신 <날짜> (N일 전)` 을 확인한다.
7일을 넘으면 `확인 필요` 에 갱신 권고가 자동으로 올라온다.
**오래된 보유 현황으로 계산한 집중도를 현재 상태처럼 말하지 않는다.**

## 3. 자산유형별로 다른 잣대를 적용한다

| basis | 자산유형 | 평가 방법 |
|---|---|---|
| `fundamental` | 개별주·리츠 | 펀더멘털 + 역DCF 가능 |
| `index_total` | 지수·섹터 ETF | 개별 펀더멘털 대신 지수 총계. **룩스루 대상** |
| `none` | 원자재 ETF·현금 | **펀더멘털이 애초에 없다**. 실질금리·달러 방향 |
| `par_yield` | 채권 ETF | 듀레이션·만기수익률 |

원자재 ETF 에 PER 같은 걸 붙이지 않는다. 리포트가 `제외: IAU — 주식 구성종목이 없어
룩스루 대상이 아니다` 라고 적는 이유다.

## 4. 표면과 실질을 구분해서 읽는다

리포트에 두 개의 집중도가 나온다:

```
표면  HHI 0.3144 · 유효 종목 수 3.18개    ← ETF 를 한 덩어리로 셀 때
실질  HHI 0.0760 · 유효 종목 수 13.15개   ← ETF 를 구성종목으로 분해했을 때
```

두 방향을 모두 짚어야 한다:
- **집중은 올라간다** — 개별주 노출이 ETF 경유분만큼 커진다 (AAPL 15.0% → 20.7%)
- **분산도 올라간다** — 5종목이 실제로는 454개 기업 노출이다

`숨은 비율 100%` 인 종목(직접 보유 0인데 실질 노출 있음)이 특히 중요하다.
"NVDA 를 한 주도 안 샀는데 실질 노출 6.5%" 같은 사실은 표면 목록만 봐선 안 보인다.

## 5. 미확보를 숨기지 않는다

- ETF 구성종목을 못 받으면 **"집중도가 과소평가된다"** 경고가 뜬다.
  SPDR 계열은 자동, iShares·Vanguard·Invesco 는 봇 차단이라
  `portfolio/etf_holdings/<티커>.csv` 에 직접 내려받아 두어야 한다.
- 시세를 못 받으면 장부가로 대체 계산되고 평가금액이 `확인 필요` 로 표기된다.
- 스냅샷이 2개 미만이면 수익 기여도를 산출할 수 없다. 편집기로 저장할 때마다 쌓인다.

## 6. 출력

리포트를 그대로 보여주고 `## 더 파볼 지점` 에 해석을 얹는다.

**리밸런싱은 계산과 시나리오만 보여준다. 목표 비중을 제시하지 않는다.**
"AAPL 실질 노출이 20.7% 로 표면보다 5.7%p 높다 — 기업 해독기로 개별 점검 대상"
까지가 이 스킬의 범위다.
