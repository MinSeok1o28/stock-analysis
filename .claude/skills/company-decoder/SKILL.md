# 기업 해독기

## 트리거
`<티커> 분석해줘` · `<회사> 어떤 회사야` · `해독해줘` · `요약 카드`

## 1. 먼저 파이프라인을 실행한다

```bash
python3 -m src.pipelines.company_decoder AAPL     # 미국
python3 -m src.pipelines.company_decoder 005930   # 한국 (6자리 종목코드)
```

`reports/cards/<티커>-decoder-<날짜>.md` 가 생성된다. **이 파일이 사실의 근거다.**
여기 없는 숫자를 만들어 쓰지 않는다. 파이프라인이 조립하는 것:

- 재무 골격 5~6년: 매출·YoY·순이익·순이익률·FCF·FCF마진 (한국은 영업이익 추가)
- **이익-현금 정합성** — 순이익과 영업현금흐름이 따로 움직이면 경고 (회계상 부풀림 신호)
- **매출 구성**: 사업부문별·제품별·지역별 표 + 매출 비중 대비 이익 기여 괴리
- **재무 건전성**: 순부채(차입−현금−단기투자), 총차입 추이, 디레버리징 여부
- `연속 증가/감소` 판정, FCF 수익률, 주당 매출
- 이상치 (FCF 3년 평균 대비 ±40%)
- 현재가·시가총액·주식수
- 미국: 10-K Item 1 발췌 2,400자 + 세그먼트 단서 문장
- 확인 필요 목록

## 2. 시장별 차이를 먼저 확인한다

| | 미국 | 한국 |
|---|---|---|
| 재무 | SEC `companyfacts` (키 불필요) | OpenDART `fnlttSinglAcntAll` (무료 키) |
| 본문 | 10-K Item 1 **자동 추출** | **미구현** — DART 뷰어 링크로 안내 |
| 핵심 지표 | 순이익률 중심 | **영업이익률 중심** |
| 단위 | B (10억) | 조 |

한국 종목은 본문이 없으므로 "돈 버는 구조"를 카드에 지어내지 말고,
DART 링크를 제시하며 **직접 확인이 필요하다고 적는다.**

## 3. 자산유형을 확인한다

카드 상단의 `평가 잣대`를 본다. `fundamental` 이 아니면 **이 스킬을 계속 쓰지 말고**
콕핏으로 보낸다. 지수·섹터 ETF 는 지수 총계로, 원자재 ETF 는
`models.AssetType.alt_metrics`(실질금리·달러 방향)로 봐야 한다.

## 4. 해석을 얹는다 — 여기부터가 사람 몫

파이프라인은 사실만 조립한다. 다음은 카드를 읽고 작성한다:

1. **돈 버는 구조** — Item 1 발췌를 읽고 mermaid 다이어그램으로. 한국은 생략하고 링크 제시.
2. **매출 구성** — 카드의 `## 매출 구성` 표를 읽는다. 사업부문별·제품별·지역별이
   SEC 렌더링 재무제표(R-file)에서 자동 추출된다. `companyfacts` 에는 차원 축이 없어
   `sec_segments.py` 가 별도로 가져온다.
   **`매출 비중 vs 이익 기여` 절이 핵심이다** — 매출 비중과 영업이익 기여가 벌어지는
   부문이 실제 돈줄이다. "매출은 37.5%인데 이익은 57%" 같은 문장이 여기서 나온다.
   표가 없으면(회사가 세그먼트를 공시하지 않거나 파싱 실패) 숫자를 지어내지 말 것.
3. **업종별 핵심 지표** — `reference/sector-metrics.md` 참조. 업종이 목록에 없으면
   가장 가까운 것을 쓰고 "대체 적용" 사실을 적는다. 지표 값 자체는 대개 카드에 없으므로
   본문 발췌로 뒷받침되는 것만 쓴다.
4. **더 파볼 지점 3개 이내** — 투자 의견이 아니라 "무엇을 더 봐야 하는지".

## 5. 서사를 파일로 남긴다 ★

해석을 채팅에만 두면 사라진다. `portfolio/narratives/<티커>.yaml` 에 쓴다.
`src/narrative_io.py` 의 `template()` 이 서식을 준다.

```bash
python3 -c "from src.narrative_io import template; print(template('NVDA'))" \
  > portfolio/narratives/NVDA.yaml
# 편집 후
python3 -m src.pipelines.stock_page NVDA     # → dashboard/stocks/NVDA.html
```

### 채울 항목과 규칙

| 항목 | 규칙 |
|---|---|
| `one_liner` | **피터 린치 2분 룰** — "2분 안에 초등학생한테 설명 못 하면 사지 말라". 업종 용어 없이 한 문장 |
| `how_it_makes_money` | 세그먼트 표의 **숫자를 근거로** 서술. 매출 비중과 이익 기여가 벌어지는 지점을 짚는다 |
| `story` | 재무 계열과 공시 문구 변화를 하나의 이야기로. 사건 → 대응 → 현재 순서 |
| `risks` | **정확히 3개.** 10-K Item 1A 에 수십 개가 있지만 아무도 안 읽는다. 영향 큰 것만 |
| `watch_next` | 다음에 확인할 것 + 어디서 |

**숫자는 카드에 있는 값만 인용한다.** 새 숫자를 만들면 출처 규칙이 무너진다.
`risks` 의 `evidence` 에 근거 위치(세그먼트 표·10-K Item 1A 등)를 적는다.

작성 후 90일이 지나면 페이지에 "갱신 권고"가 뜬다.

## 6. "답이 안 나온 것"을 지우지 않는다

카드에 두 개의 절이 있고 성격이 다르다:

| 절 | 의미 |
|---|---|
| `확인 필요 (데이터 미확보)` | 시스템이 데이터를 못 받았다 |
| `이 카드로 답이 안 나온 것` | **자료 자체로 답할 수 없는 질문** + 다음에 볼 문서 |

두 번째가 더 중요하다. "DTC 흑자가 구조적인가 일시적인가 → 최근 분기 어닝콜 확인"처럼
**다음 행동**을 짚는다. 둘 다 산출물에 남긴다.

## 7. 출력

카드 파일을 그대로 보여주되, 위 해석을 `## 돈 버는 구조` 와 `## 더 파볼 지점` 에 채운다.
`[사실]`/`[해석]` 표기를 유지한다. 카드의 `## 확인 필요` 절을 지우지 않는다.
